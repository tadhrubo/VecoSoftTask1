Primary Objective:
Design a clean, premium, production-ready order tracking screen optimized for 360–430px mobile viewports that expands seamlessly into an intelligent desktop layout. Do not overcomplicate it with excessive dashboard cards or heavy 3D visuals; keep it restrained, clear, and data-driven.

Requirements & Edge Cases to Support:
The UI must be entirely data-driven, allowing the viewer to inspect 4 states:
1. Standard State: Successful delivery progress (Ordered -> Confirmed -> Shipped -> Out for Delivery -> Delivered).
2. Delayed Order: ETA has passed or delivery is delayed. Prominently display an alert/status message, updated ETA, and clear next steps (e.g., Track Updates / Contact Support).
3. Delivered but Not Received: System marks it as delivered, but the user hasn't received it. Provide specific guidance (e.g., check surroundings/neighbors) and a direct report/support action.
4. Tracking Not Available Yet: Order exists and is confirmed, but tracking info is pending from the carrier. Display an intentional, non-broken placeholder state with estimated window and support options.

Component & Layout Architecture:
- Root Layout / Page: Mobile-first container (`max-w-md mx-auto min-h-screen p-4 md:max-w-4xl md:grid md:grid-cols-2 md:gap-8`).
- Header: Order number, estimated delivery date/time, and clear delivery status pill/badge.
- Delivery Timeline (Hero): Clean visual vertical stepper showing current progress, dates/timestamps, and clear active/completed/pending step indicators.
- Order & Item Summary: Compact product details (item name, thumbnail placeholder, pricing, quantity).
- Dynamic Action / Support Card: Context-sensitive actions based on the active state (Contact Support, Report Missing Package, etc.).
- Evaluator Bar: A fixed, discreet bottom toolbar for demonstration purposes allowing quick switching between the 4 states: ['STANDARD', 'DELAYED', 'NOT_RECEIVED', 'PENDING'].
